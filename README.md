# project-workflow

새 프로젝트를 시작할 때와 새 버전을 시작할 때 참고하는 **문서 묶음**이다.

도구가 아니다. 설치할 것도 실행할 것도 없다. 읽고 따른다.

---

## 무엇을 푸는가

**MVP 이후가 눈에 안 보이는 문제.**
결과물을 고치고 개선할 때 진행이 커밋에만 남는다. 커밋 이력은 남는 것이지
읽히는 것이 아니다.

**같은 준비를 프로젝트마다 반복하는 문제.**
폴더를 어떻게 잡고 무엇을 기록할지 매번 다시 정한다.

---

## 무엇을 하지 않는가

- **자동화하지 않는다.** 스킬이나 생성기를 만들지 않는다. 반복해서 직접 해봐야 몸에 남는다
- **문서를 대신 써주지 않는다.** 무엇을 만들지는 사람이 정한다
- **빈 양식을 제공하지 않는다.** 형식은 정의하되 통째로 복사하는 뼈대는 두지 않는다

---

## 어떻게 쓰는가

**한 번만 — 클론한다**

```
git clone <this-repo> d:/tools/project-workflow
```

프로젝트 안으로 복사하지 않는다. 사본이 생기면 갱신돼도 옛 것을 따르게 된다.

**새 프로젝트를 시작할 때**

```
mkdir my-project
cd my-project
# README.md 와 5종 문서를 여기 넣는다
claude
```

```
d:/tools/project-workflow/docs/INIT.md 를 읽고 이 프로젝트를 초기화해줘.
```

이후 단계별 지시문은 `docs/PROMPTS.md`에 있다. 복사해서 쓴다.

## 이 방식이 세우는 구조

```
<project>/
├── README.md             이 프로젝트가 무엇인가
├── CLAUDE.md             지켜야 할 제약. 매 세션 로드
├── .claude/              rules · hooks · agents
└── docs/
    ├── current/          현재 버전 6종
    ├── history/v0.1/     지난 버전 6종. 불변
    └── analysis/         조사·실측
```

**두 층이다.** 루트는 프로젝트 전체에 걸리는 것, `docs/current/`는 이번 버전 것.
어디 있는지가 그 문서의 수명을 말한다.

---

## 6종 문서

| 문서 | 담는 것 | 누가 |
| --- | --- | --- |
| `BRIEF.md` | 배경, **이번 버전에서 풀고 싶은 문제** | 사람 |
| `DECISIONS.md` | 설계 결정과 근거, **배제한 대안** | 사람 |
| `SPEC.md` | 요구사항 · 제약 · **미구현 대상** | 사람 |
| `PLAN.md` | Phase 배열과 완료 조건 | 사람 |
| `backlog.json` | task 분해. **계획한 것**의 SSOT | 사람 |
| `PROGRESS.md` | 진행 기록. **실제로 한 것** | 에이전트 |

**버전마다 여섯 개를 새로 쓴다.** 누적하지 않는다.
`docs/history/v0.1/`을 열면 그 폴더만으로 그 버전이 완결된다.

---

## 알아둘 것 셋

**전 Phase 완료는 버전 마감이 아니다.**
backlog를 다 소진해도 사람이 써보고 손볼 곳이 나온다. 그 검토까지가 그 버전이다.

**계획 외 개선은 backlog에 넣지 않는다.**
`PROGRESS.md`에 적는다. 그래야 마감 때 "계획 대비 무엇이 더 붙었는지"가 보이고,
그게 다음 버전 `BRIEF`의 재료가 된다.

**hook은 등록만으로 동작하지 않는다.**
설치 직후 가짜 입력으로 실제 막히는지 확인한다. 조용히 무력화되는 일이 흔하다.

## 전제

| 항목 | 확인 |
| --- | --- |
| backlog CLI | 설치돼 있고 실행된다 |
| 이 레포 | 로컬에 클론돼 있다 |

없으면 시작하지 않는다. **프로젝트 안에서 설치하지 않는다.**
